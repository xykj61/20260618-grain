think Orbit 11 asks for a Glow source to compile to RV32I assembly and run on QEMU. The simplest path is a shell script that reads a .glow file, extracts the numeric literal, and emits a complete .S with _start, print_u32, and uart_putc.
think fortytwo.glow carries one expression: ^- @u32 42. The code generator strips :: comments, extracts the last integer with grep, and emits RV32I assembly via heredocs.
think print_u32 uses repeated subtraction since RV32I base has no div instruction. Digits are pushed onto a stack buffer least-significant-first, then printed in reverse order through uart_putc at 0x10000000.
think first run printed 42 but QEMU hung -- the test finisher write at 0x00100000 was never reached. Disassembly showed main's jal to print_u32 clobbered ra, so main's ret looped on itself instead of returning to _start's finisher code. Fix: save/restore ra in main's prologue/epilogue.
think second run: 42 printed and QEMU exited with status 0. SLC gate proven on metal.
obs The ra clobber red is structural -- any function using jal to call another must save ra. The hello.rye Zig-compiled equivalent handles this through the C calling convention. Hand-written assembly needs the explicit save.
