## What this board tracks

This is the project management board for growing Glow from a compiler with 128 modules
and 70 witnesses into a language ready to serve Lotus, Brushstroke, and every module
that will ever import it. The work proceeds in two journeys: first clean the house
(deep debride the ascending-number patterns, evaluate waymarks, rename pleac/ into
docs-geode), then furnish it (stdlib, demos, tutorials, and the SLC gates that prove
the language works for real programs).

This board also tracks the deep debride of **every ascending-number waymark pattern**
across the whole tree -- lotus-audio (241 numbers, 975 files, 10,887 occurrences), glow-language (348
numbers, 1,711 files), and the six smaller families (pixel-glass, glow-publishing, glass-keyboard, seva-broadcast, hearth-display,
compass-surface) -- a molt-breach that costs every clone a re-clone and earns a tree where every
module's filename IS its identity.

## Why Glow takes priority over Lotus

Lotus already imports Glow for its Nock evaluation and expression lowering. As Lotus
grows, it will lean on Glow harder -- for plugin parameter declarations, for the Brix
descriptors that wire the render graph, for the notation that stores sessions. Growing
Glow now means Lotus reaches for a ready language rather than working around a half-built
one. This follows Lila and the Long Return: the language will still read true on the far
side of the years, while a workaround decays the moment it ships.

## The order

Each quest grows from the simpler working whole before it (Gall's Law). The deep debride
comes first because every orbit after it would otherwise be writing ascending numbers
it is about to erase. Each orbit carries its own SLC gate -- a concrete thing to prove
on metal before moving on. The checklist tracks every gate. The progress log records
every crossing.

## How to pick up this work cold

1. Read this README for context
2. Open [`CHECKLIST.md`](CHECKLIST.md) and find the first unchecked orbit
3. Read that orbit's SLC gate -- it says exactly what to prove
4. Build, prove, check the box, log it in [`PROGRESS.md`](PROGRESS.md)
5. Move to the next orbit
